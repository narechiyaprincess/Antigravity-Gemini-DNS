# S03: bounded scenario diagnostics

These commands belong to a separately built candidate. They do not install or apply a route.

```
AntigravityGeminiDns.exe --scenario-contract-test
AntigravityGeminiDns.exe --scenario-probe-system
AntigravityGeminiDns.exe --scenario-probe-provider geohide
```

The probe commands return JSON and exit **2**, because transport evidence does not establish application readiness. A provider argument must name an embedded catalog profile. Arbitrary URLs, addresses, paths, credentials and request bodies cannot be supplied. Mixed mutation commands and noncanonical scenario flags are rejected before settings or the native engine are loaded.

The finite endpoint set is the four exact core/Gemini catalog hosts. Each receives DNS A/AAAA, then at most one pinned public IPv4 and one pinned public IPv6 TCP/TLS connection followed by **HEAD https://original-host/**. Original hostname SNI, chain trust and name validation remain enabled. No proxy, cookie, authorization header, client certificate, redirect, retry, GET fallback or model API request is used. AIA downloads and revocation lookups are disabled for bounded TLS work; revocation is explicitly unmeasured. An unknown chain remains a failure. A system lookup inherits Windows policy/cache/hosts. A provider lookup pins its first catalog bootstrap address and keeps the provider URI/SNI; it also observes HTTPS/SVCB records. Neither path establishes how a browser or desktop client resolves its requests, nor bypasses the current VPN/TUN.

Limits are 4 seconds per operation, 90 seconds per run, four hosts, eight A/AAAA lookups, at most eight destination connections, eight provider-only modern RR queries, 64 addresses per answer, 65,535 DoH body bytes, 16 KiB cumulative HTTP headers and eight informational responses. A HEAD response body is never read. Large Content-Length on HEAD describes a hypothetical GET representation and is not a downloaded body. DoH header and body work use the same operation token; noncooperative injected tasks cannot extend the caller deadline. A network event or changed snapshot/policy invalidates the run. Receipts carry client/scenario/network/pack/provider/policy revisions, observed/expiry timestamps and individual layer outcomes; the five-minute window is an evidence budget, not a DNS TTL or service availability guarantee.

HTTP statuses retain resource semantics: 2xx is reachability with operation **UNKNOWN**; 3xx is unfollowed; 401/403 is a resource authentication/permission refusal rather than an account diagnosis; 404/405 may mean unsupported root/method; 429 and 5xx are refusals. A malformed response, oversized body/header or nonpublic address never becomes success. The destination classifier intentionally rejects some globally routable special ranges. Public IP checks cannot identify a malicious public gateway; original-name TLS is still required.

The additive RFC 9460 parser observes bounded HTTPS/SVCB metadata. It distinguishes AliasMode/root service-unavailable from ServiceMode/root owner-name, rejects compressed TargetName, truncation and malformed/duplicate/out-of-order parameters, marks unknown mandatory keys incompatible, and preserves ALPN, port, hints, opaque ECH and unknown optional bytes. It never follows aliases/hints, changes routes/ports, strips AAAA/ECH or claims usable ECH. Key 5 is opaque, including its RFC 9848 length prefix; its configuration is not validated. System modern RR, browser Secure DNS, QUIC, ECH execution and the full auth/CDN/upload dependency graph remain unmeasured.

Authorized operation/stream checks are voluntary actions in the real client. `UserScenarioEvidence` accepts only explicit voluntary attestation, matching complete context and a valid observation window. Unknown/skipped/stale/wrong-client evidence stays UNKNOWN; a request refusal or interrupted stream stays FAILED. A fully passed attestation describes only the selected scenario. The network-only S01 reducer is unchanged. Conversation receipts must say **user attested**, identify the running binary (path/hash plus app/runtime version where available), and preserve what was and was not directly observed. A runtime version may identify the embedded shell rather than the product version. Never search for credentials or issue hidden generation calls.

The limited S03 lab covers IPv4-only, dual-stack, absent/nonpublic IPv6, poison, timeout, TCP/TLS/refusal, context change, limits and modern records with fixtures. Actual network receipts add only the network cells that were measured. A transport timeout and a successful user client can coexist; neither proves the other's resolver or egress. Do not turn off VPN/IPv6/DoH or repair Windows to fill a matrix cell.

Primary contracts: [HTTP safe methods and HEAD (RFC 9110)](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.2), [SVCB/HTTPS wire format (RFC 9460)](https://www.rfc-editor.org/rfc/rfc9460.html#section-2.2), [ECH key format (RFC 9848)](https://www.rfc-editor.org/rfc/rfc9848.html#section-3), [IANA IPv4 special ranges](https://www.iana.org/assignments/iana-ipv4-special-registry/), [IANA IPv6 special ranges](https://www.iana.org/assignments/iana-ipv6-special-registry/), [.NET TLS chain policy](https://learn.microsoft.com/en-us/dotnet/api/system.net.security.sslclientauthenticationoptions.certificatechainpolicy?view=net-10.0), [AIA download control](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509chainpolicy.disablecertificatedownloads?view=net-10.0). Vendor operations require separate authorization and account conditions: [Gemini generation API](https://ai.google.dev/api/generate-content), [API keys](https://ai.google.dev/gemini-api/docs/api-key), [API errors](https://ai.google.dev/gemini-api/docs/generate-content/api-errors?hl=en), [regions](https://ai.google.dev/gemini-api/docs/available-regions), [pricing](https://ai.google.dev/gemini-api/docs/pricing), [Antigravity FAQ](https://www.antigravity.google/docs/faq/), [Gemini Windows](https://support.google.com/gemini/answer/18263854?hl=en-6). No documented free unauthenticated operation/stream health contract was established for the four catalog hosts. Root HEAD is a standards-based transport control with possible incidental server logging, not a vendor health endpoint.
