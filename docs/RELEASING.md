# Локальная подготовка релиза

1. Сохранить source preimage и список изменений, зафиксировать SDK, версию и
   происхождение исходников. Не сбрасывать untracked/dirty файлы.
2. Выполнить [сборку и offline gate](BUILDING.md). Не менять DNS работающего
   компьютера ради полной зелёной таблицы. Ошибку gate исправить и перепроверить;
   непроведённую live проверку обозначить явно.
3. Создать новый каталог поставки с `Source Code/`, `Release/` и одним
   `RELEASE_REPORT_v1.1.0.md`. Диагностику и экспериментальные бинарники хранить
   за пределами этого каталога.
4. `package-source.ps1 -OutputPath <новый staging.zip>` отбирает исходники,
   тесты, ресурсы, SDK/build configs и документацию. Он исключает generated outputs,
   историю локальных работ и корневые рабочие заметки; подозрительные ключи и
   бинарники в выбранных путях вызывают отказ. Проверить список ZIP, распаковать
   в `Source Code`, сверить хеши и сохранить staging ZIP вне поставки.
5. Собрать `Source Code` независимо с новым `-BuildRoot` и output вне поставки.
   Прогнать безопасные проверки из этой копии, затем убрать только собственные
   generated outputs из source-копии. Перед удалением проверить абсолютный scope.
6. Принятый single-file EXE скопировать как
   `Release/Antigravity-DNS-v1.1.0-win-x64.exe`. Проверить именно переименованный
   файл через `--version`, `--self-test`, `--verify-scripts`, synthetic UI и отдельно
   в пустой папке. Запуск обычного GUI может перепривязать собственный включённый
   автозапуск: тестировать synthetic modes либо изолированный профиль.
7. Записать SDK/options/provenance/размер/подпись в `BUILDINFO.txt`, вычислить
   `SHA256SUMS.txt` после окончательного копирования и повторно проверить.
   Между последней проверкой и хешированием бинарник не заменять.
8. Указать известные риски, P0/P1, действительные логи и ограничения среды в отчёте.
   Непройденный обязательный gate означает BLOCKED, а отсутствие live mutation
   при пройденных offline gates допускает READY WITH DOCUMENTED LIMITATIONS.

`Package.ps1` — дополнительная ZIP-упаковка; checksum относится к поставляемому
ZIP. `package-release.ps1` заменяет только локальные EXE/ярлык с preimages и receipt;
это действие не требуется для независимого финального каталога. `verify.ps1`
делает такую замену только с явным `-Publish`.

Этот процесс не выполняет commit, tag, push, PR или GitHub Release. Публикация —
отдельное действие владельца. Без легитимного сертификата EXE остаётся unsigned;
отсутствие подписи указывается, не обходится фиктивным сертификатом.

## Замороженный v1.1.0 и публикация

Для текущего v1.1.0 принят ранее проверенный комплект. Не пересобирайте и не заменяйте его EXE для загрузки из CI. Официальное имя asset — `Antigravity-DNS-v1.1.0-win-x64.exe`, размер — 52372130 bytes, SHA-256 — `B361DDE5FC8E4F06841100C7C67D37AD081462D9082C2F96A2EDAB2688F7D915`. С ним распространяются неизменённые `BUILDINFO.txt`, `LICENSES.txt`, `SHA256SUMS.txt`.

Репозиторий называется `Antigravity-DNS`; продукт — `Antigravity-Gemini DNS`; build target — `AntigravityGeminiDns.exe`. Имена имеют разные назначения.

CI выполняет только build/offline verification. `release.yml` запускается вручную и загружает только логи; tag trigger, создание Release и загрузка бинарников отсутствуют. Старый шаблон в `src/tools/ci/build.yml` также manual-only.

После интеграции source/docs/CI и успешного push browser-этап проверяет Actions, отображение README/ссылок и commit; затем отдельно создаёт tag `v1.1.0`, GitHub Release и прикрепляет точные утверждённые assets. Проверить скачанный EXE и SHA-256. Не публиковать до разрешения blockers. Дата подготовки исходников не считается датой публикации Release.
